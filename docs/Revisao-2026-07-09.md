## 🩹 Problemas encontrados e correções

### 1. Ruído de fim de linha (CRLF) — CORRIGIDO
Todos os ~55 arquivos apareciam como "modificados" no `git status`, mas o conteúdo é idêntico — só mudança de `LF` → `CRLF` causada pela sincronização OneDrive/Windows. Isso torna o `git status` inutilizável.

- [x] Criado `.gitattributes` com `* text=auto eol=lf` para o git guardar sempre LF.
- [ ] **Ação sua (no Windows):** rodar uma vez para limpar o ruído:
  ```bash
  git add --renormalize .
  git commit -m "chore: normaliza fim de linha (LF via .gitattributes)"
  ```

### 2. `.git/index.lock` órfão — AÇÃO SUA
Existe um `.git/index.lock` de 0 bytes travando escritas do git (sobra de um processo interrompido). Não consegui removê-lo do sandbox Linux (permissão OneDrive).

- [ ] **Ação sua:** deletar o arquivo `judotracker/.git/index.lock` no Windows.

## ⚠️ Observações de código (não são bugs, mas vale rever)

- **`updateAthlete` (backend/src/index.ts:234):** faz `coachId: input.coachId || null`. Numa atualização parcial sem `coachId`, isso **apaga** o treinador do atleta. Se a intenção for edição parcial, usar `undefined` quando o campo não vier.
- **Roles por lista fixa (auth/index.ts:31):** `COACH_EMAILS` está hardcoded no código. Funciona para MVP, mas idealmente virava uma flag no banco ou Firebase custom claims.
- **`sex` no schema Prisma existe mas não está exposto no typeDefs GraphQL** — só um campo não usado, sem impacto.
- **Sem testes automatizados e sem ESLint** em nenhum dos lados. Para um projeto que já tem CI, vale adicionar ao menos smoke tests.
- **`frontend/dist/` está versionado** — normalmente build gerado não vai pro git.
